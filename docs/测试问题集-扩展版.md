## B. 根据需求生成高质量代码（按需求类型）

统一质量门槛（B 类全部适用）：
1. 关键结构走工具链：`get_symbol_code` ≥ 4 次，且四类角色（VO / 校验绑定 / 组装 / 实体表）都读到（放款域）；其他域至少覆盖「入参 VO + Service 实现 + 实体/Mapper」。
2. 实体、Mapper、表名、字段必须来自证据（`@TableName` 与实体字段），禁止编造。
3. 风格对齐：`Request<T>/Response<T>` 包装、`ResponseBuilder`、日志 `log.info("methodName:...")` 风格、字段名常量类风格（`FieldNameConstants`）。
4. 不可把「流程综述/持久化关卡清单」当作改造方案；不可出现「评审提示」「补充说明」脚注样式。
5. MyBatis-Plus 项目：新增列通常不需要改 ExtMapper.xml；需要时明确说明。
6. 证据不足处必须明说，不硬编。

## F. 评测建议

1. **回归门禁**：A 类每域取 2-3 条 + B 类正例（B1/B4/B7/B9/B11/B12）+ C 类全量 + D 类全部，
   作为每次改动后的关键字判定回归（弱模型下稳定：必含命中 + 必禁词 0 命中）。
2. **加分项（LLM-as-judge）**：A/B 类追加「证据一致性」评分——回答中出现的类名/方法名/表名
   与检索证据做集合比对，出现证据外名词即扣分（复用 `answer_reviewer.invented_tables_not_in_evidence`）。
3. **多轮稳定性**：C4/C5/C6 判定每轮 `last_class_method` 是否保持/正确切换（复用 smoke 的 `_lock_ok`）。
4. **代码生成质量**：
   - B1：`get_symbol_code` ≥ 4 且 vo/bind/assemble/ext 四类角色都读到；DDL 段与 `FieldNameConstants` 风格；
   - B4/B5/B6/B13：生成代码引用的 Class/字段 ∈ 证据集；
   - B7/B8/B9：KB 规格解析字段与 ReqVo/RespVo 一一对应；entity_only 不带 Controller/Service；
   - B11/B12：队列名/任务名/表名来自真实注解与实体。
5. **新增域注意**：A2/A3/A5/A8 的问题集若第一次跑失败集中在「入口未锁定」，优先补
   结构化流程文档命中（`_pick_structured_flow_doc`）与路由文本（同 test_repay_flow_pick、
   test_risk_callback_entry_pick 的做法），不要改问题本身。
